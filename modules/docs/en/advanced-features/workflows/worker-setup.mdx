Workflow is a system for executing **background tasks**. Use it for email sending, data processing, scheduled jobs, and more.

## Tasks Configuration

```typescript
// sonamu.config.ts
import { defineConfig } from "sonamu";

export default defineConfig({
  // ...
  tasks: {
    enableWorker: true, // Enable Worker
    workerOptions: {
      concurrency: 4, // Concurrent execution count
      usePubSub: true, // Use Pub/Sub
      listenDelay: 500, // Listen delay (ms)
    },
    contextProvider: async (baseContext) => {
      // Configure Context used in Workflows
      return {
        ...baseContext,
        // Custom data can be added
      };
    },
  },
});
```

**Options**:

- `enableWorker`: Whether to enable Worker (default: `true` only when `NODE_TYPE=daemon`)
- `workerOptions.concurrency`: Number of concurrent tasks (default: CPU core count - 1)
- `workerOptions.usePubSub`: Use PostgreSQL LISTEN/NOTIFY (default: true)
- `workerOptions.listenDelay`: Wait time after receiving Pub/Sub message (default: 500ms)
- `contextProvider`: Function to create Context used within Workflows

## WorkflowManager

Sonamu automatically creates and manages the `WorkflowManager`. Access it via `Sonamu.workflows`.

```typescript
import { Sonamu } from "sonamu";

// Run Workflow
const workflowManager = Sonamu.workflows;
const handle = await workflowManager.run(
  {
    name: "send_email",
    version: null,
  },
  { email: "user@example.com" },
);

// Wait for result
const result = await handle.result();
```

## Worker Modes

### 1. Daemon Mode (Auto-enabled)

There is no separate daemon command. When `tasks.enableWorker` is not set, Sonamu enables the Worker
only for processes started with `NODE_TYPE=daemon`. The Worker is created during `Sonamu.init()` and
started after the server begins listening.

```bash
# Start the built server as a daemon node; the Worker starts with it
NODE_TYPE=daemon pnpm sonamu start
```

Set `enableWorker` explicitly to override this detection on any node.

### 2. Separate Worker Process

```typescript
// src/worker.ts
import { Sonamu } from "sonamu";

async function startWorker() {
  await Sonamu.init(true, false);

  await Sonamu.workflows.startWorker();

  console.log("Worker started");

  // Graceful shutdown
  const shutdown = async () => {
    console.log("Stopping worker...");
    await Sonamu.workflows.stopWorker();
    process.exit(0);
  };

  process.on("SIGTERM", shutdown);
  process.on("SIGINT", shutdown);
}

startWorker();
```

```json
// package.json
{
  "scripts": {
    "worker": "tsx src/worker.ts",
    "worker:dev": "tsx watch src/worker.ts"
  }
}
```

```bash
# Run Worker
pnpm worker
```

`startWorker()` starts only the Worker that `Sonamu.init()` created. Set `tasks.enableWorker: true`
or run this process with `NODE_TYPE=daemon`; otherwise it initializes the task backend without a
Worker.

### 3. API Server + Worker

```typescript
// sonamu.config.ts
export default defineConfig({
  tasks: {
    enableWorker: true, // Run Worker in API server too
    workerOptions: {
      concurrency: 2, // Lower concurrency for API server
    },
    contextProvider: async (baseContext) => baseContext,
  },
});
```

## Distributed Workers

You can run Workers on multiple servers.

```typescript
// Server 1, 2, 3...
tasks: {
  enableWorker: true,
  workerOptions: {
    concurrency: 4,
    usePubSub: true,
  },
}
```

PostgreSQL acts as the task queue, and Workers communicate via Pub/Sub.

## Context Provider

Customize the Context used in Workflows.

```typescript
// sonamu.config.ts
tasks: {
  enableWorker: true,
  contextProvider: async (defaultContext) => {
    // Look up the system user
    const systemUser = await BaseModel.getPuri("r")
      .table("users")
      .select({ id: "users.id" })
      .where("users.email", "system@example.com")
      .first();

    return {
      ...defaultContext,
      systemUserId: systemUser?.id ?? null,
    };
  },
}
```

Declare custom fields such as `systemUserId` in `ContextExtend` so they are typed.

Access via `Sonamu.getContext()` within a Workflow function:

```typescript
import { workflow } from "sonamu";
import { Sonamu } from "sonamu";

export const myWorkflow = workflow({ name: "my_workflow" }, async ({ input, step }) => {
  const context = Sonamu.getContext();
  console.log(context.systemUserId);
});
```

## Table Structure

The task backend runs its own migrations and creates the `sonamu_tasks` schema in the main database
with two tables:

| Table                         | Contents                                                                                       |
| ----------------------------- | ---------------------------------------------------------------------------------------------- |
| `sonamu_tasks.workflow_runs`  | One row per run: `workflow_name`, `version`, `status`, `input`, `output`, `error`, `attempts`, timestamps |
| `sonamu_tasks.step_attempts`  | One row per step attempt: `workflow_run_id`, `step_name`, `status`, `output`, `error`, timestamps |

## Monitoring

### Check Running Workflows

```typescript
// workflow_runs is a framework-internal table, not an entity, so use Knex directly
import { BaseModel } from "sonamu";

const knex = BaseModel.getDB("r");
const runs = await knex
  .withSchema("sonamu_tasks")
  .table("workflow_runs")
  .where("status", "running")
  .select();
```

### Logging

```typescript
export const myWorkflow = workflow({ name: "my_workflow" }, async ({ logger, input }) => {
  logger.info("Workflow started", { input });
  logger.error("Error occurred", { error });
});
```
