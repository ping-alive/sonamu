## @api Decorator

<AccordionGroup>
<Accordion title="How do I use the @api decorator?">

Attach the `@api` decorator to Model or Frame class methods to create REST API endpoints.

**Basic usage:**

```typescript
class UserModelClass extends BaseModelClass {
  @api({ httpMethod: "GET" })
  async getProfile(id: number): Promise<UserSubsetMapping["A"]> {
    return this.findById("A", id);
  }

  @api({ httpMethod: "POST" })
  async saveUsers(spa: UserSaveParams[]): Promise<number[]> {
    return this.save(spa);
  }

  @api({ httpMethod: "DELETE" })
  async deleteUsers(ids: number[]): Promise<number> {
    return this.del(ids);
  }
}
```

**Auto-generated endpoints:**

```
GET    /api/user/getProfile?id=1
POST   /api/user/saveUsers
DELETE /api/user/deleteUsers
```

With the default `api.route.prefix` of `/api`, the paths are `/api/{model}/{method}`. GET parameters are read from the query string; other methods read the JSON body.

</Accordion>

<Accordion title="What are the options for @api decorator?">

**httpMethod (default: `"GET"`):**

```typescript
@api({ httpMethod: "GET" | "POST" | "PUT" | "DELETE" | "PATCH" })
```

**guards (authentication/authorization):**

```typescript
// Authentication and authorization required
@api({
  httpMethod: "POST",
  guards: ["user", "admin"]  // user login required, admin permission required
})
async adminOnly() { }

// Public API (no authentication required)
@api({
  httpMethod: "GET"
  // Omit guards to allow access without authentication
})
async publicApi() { }
```

<Info>
  **Creating Public APIs**: Omit the `guards` option to create a public API accessible to anyone
  without authentication. Use this for endpoints that don't require login or permission checks.
</Info>

**path (custom path):**

```typescript
@api({
  httpMethod: "GET",
  path: "/custom/path"  // Use /custom/path instead of /user/method
})
async customPath() { }
```

</Accordion>

<Accordion title="How do I receive parameters in GET requests?">

**Query parameters (single values):**

```typescript
@api({ httpMethod: "GET" })
async getUser(id: number, includeProfile?: boolean): Promise<User> {
  // GET /user/getUser?id=1&includeProfile=true
}
```

**Query parameters (object):**

```typescript
@api({ httpMethod: "GET" })
async listUsers(listParams: UserListParams): Promise<ListResult<UserListParams, User>> {
  // GET /user/listUsers?num=20&page=1&orderBy=id-desc
  return this.list("A", listParams);
}
```

</Accordion>

<Accordion title="How do I receive body in POST requests?">

**Single object:**

```typescript
@api({ httpMethod: "POST" })
async createUser(params: UserSaveParams): Promise<User> {
  // POST /user/createUser
  // Body: { name: "John", email: "john@example.com" }
  return this.save(params);
}
```

**Multiple parameters:**

```typescript
@api({ httpMethod: "POST" })
async updateProfile(
  userId: number,
  profile: ProfileSaveParams
): Promise<Profile> {
  // POST /user/updateProfile
  // Body: { userId: 1, profile: { bio: "..." } }
  return ProfileModel.save({ user_id: userId, ...profile });
}
```

</Accordion>

<Accordion title="How do I create a file upload API?">

The `@upload` decorator is used independently without `@api`.

**Single file:**

```typescript
import { upload, Sonamu } from "sonamu";

@upload()
async uploadAvatar(): Promise<{ url: string; filename: string }> {
  // POST /user/uploadAvatar
  // Content-Type: multipart/form-data

  const { bufferedFiles } = Sonamu.getContext();
  const file = bufferedFiles?.[0]; // Use first file

  if (!file) {
    throw new Error("File is required");
  }

  const md5 = await file.md5();
  const key = `avatars/${md5}.${file.extname}`;
  const url = await file.saveToDisk("fs", key);

  return { url, filename: file.filename };
}
```

**Multiple files:**

```typescript
import { upload, Sonamu } from "sonamu";

@upload()
async uploadFiles(): Promise<{ files: Array<{ url: string; filename: string }> }> {
  // POST /user/uploadFiles
  // Content-Type: multipart/form-data

  const { bufferedFiles } = Sonamu.getContext();

  if (!bufferedFiles || bufferedFiles.length === 0) {
    throw new Error("At least one file is required");
  }

  const results = [];
  for (const file of bufferedFiles) {
    const md5 = await file.md5();
    const key = `files/${md5}.${file.extname}`;
    const url = await file.saveToDisk("fs", key);
    results.push({ url, filename: file.filename });
  }

  return { files: results };
}
```

</Accordion>

<Accordion title="How do I return errors?">

**BadRequestException (400):**

```typescript
import { BadRequestException } from "sonamu";

@api({ httpMethod: "POST" })
async createUser(params: UserSaveParams): Promise<User> {
  if (!params.email) {
    throw new BadRequestException("Email is required");
  }
  return this.save(params);
}
```

**UnauthorizedException (401):**

```typescript
import { UnauthorizedException } from "sonamu";

@api({ httpMethod: "GET" })
async getMyProfile(): Promise<User> {
  const userId = Sonamu.getContext().user?.id;
  if (!userId) {
    throw new UnauthorizedException("Login is required");
  }
  return this.findById("A", userId);
}
```

**Permission error (403):**

```typescript
import { UnauthorizedException } from "sonamu";

@api({ httpMethod: "DELETE" })
async deleteUser(id: number): Promise<void> {
  const currentUser = Sonamu.getContext().user;
  if (currentUser?.role !== "admin") {
    throw new UnauthorizedException("Admin permission required");
  }
  await this.del(id);
}
```

**NotFoundException (404):**

The generated `findById` already throws `NotFoundException` when the record does not exist. Use `findOne`, which returns `null`, when you need your own handling:

```typescript
import { NotFoundException } from "sonamu";

@api({ httpMethod: "GET" })
async getUserOrFail(id: number): Promise<UserSubsetMapping["A"]> {
  const user = await this.findOne("A", { id });
  if (!user) {
    throw new NotFoundException("User not found");
  }
  return user;
}
```

</Accordion>
</AccordionGroup>

## Context and Session

<AccordionGroup>
<Accordion title="How do I get current logged-in user information?">

```typescript
import { Sonamu } from "sonamu";

@api({ httpMethod: "GET" })
async getMyProfile(): Promise<User> {
  const context = Sonamu.getContext();
  const userId = context.user?.id;

  if (!userId) {
    throw new UnauthorizedException("Login is required");
  }

  return this.findById("A", userId);
}
```

</Accordion>

<Accordion title="What information is in Context?">

```typescript
const context = Sonamu.getContext();

// Auth info (better-auth)
context.user; // Logged-in user (null if unauthenticated)
context.session; // Session (null if unauthenticated)
context.user?.id; // User ID

// Request info
context.transport; // "http" | "ws"
context.headers; // Request headers (IncomingHttpHeaders)
context.headers["user-agent"]; // User-Agent
context.locale; // Locale of the current request

// Fastify objects (when transport === "http")
context.request; // FastifyRequest (use context.request.ip for client IP)
context.reply; // FastifyReply

// Naite log store
context.naiteStore;
```

<Info>
  `userId`/`ip`/`userAgent` are not top-level properties on Context. Use
  `context.user?.id`, `context.request.ip`, and `context.headers["user-agent"]`
  respectively.
</Info>

</Accordion>

<Accordion title="How do I use sessions?">

Sessions are managed by better-auth. Enable it with `server.auth`; there is no separate session
setting.

```typescript
// sonamu.config.ts
export default defineConfig({
  server: {
    auth: {
      emailAndPassword: { enabled: true },
      session: {
        expiresIn: 60 * 60 * 24, // 24 hours (seconds)
      },
    },
  },
});
```

**Sign in / sign out**: clients call the better-auth endpoints (`POST /api/auth/sign-in/email`,
`POST /api/auth/sign-out`), usually through `authClient` from `better-auth/react`. You do not write
login APIs that store values in a session.

**Read the session** in any API:

```typescript
@api({ httpMethod: "GET" })
async getMyInfo() {
  const { user, session } = Sonamu.getContext();

  if (!user || !session) {
    throw new UnauthorizedException("Login is required");
  }

  return this.findById("A", user.id);
}
```

`session` is read-only session metadata (`expiresAt`, `ipAddress`, `userAgent`, ...). Store
per-user data in your own entities instead of the session.

→ [Session Management](/en/api-development/authentication/session-management)

</Accordion>
</AccordionGroup>

## Authentication and Authorization

<AccordionGroup>
<Accordion title="How do I control permissions with Guards?">

**Guard implementation:** guard keys (`user`, `admin`, `query`) are checked in
`server.apiConfig.guardHandler`. It runs inside the request context, so `Sonamu.getContext()`
returns the current `user`. Throw to reject the request.

```typescript
// sonamu.config.ts
import { defineConfig, Sonamu, UnauthorizedException } from "sonamu";

export default defineConfig({
  server: {
    auth: {
      emailAndPassword: { enabled: true },
    },
    apiConfig: {
      // ... contextProvider
      guardHandler: (guard) => {
        const { user } = Sonamu.getContext();

        if (guard === "user" && !user) {
          throw new UnauthorizedException("Login is required");
        }
        // Requires a role field added to the User entity
        if (guard === "admin" && (user as { role?: string } | null)?.role !== "admin") {
          throw new UnauthorizedException("Admin permission required");
        }
      },
    },
  },
});
```

**Using Guards:**

```typescript
// user login required
@api({ httpMethod: "GET", guards: ["user"] })
async getMyProfile() {
  const { user } = Sonamu.getContext();
  return this.findById("A", user!.id);
}

// admin permission required
@api({ httpMethod: "DELETE", guards: ["admin"] })
async deleteUsers(ids: number[]): Promise<number> {
  return this.del(ids);
}
```

<Info>
  When several guards are listed, `guardHandler` runs for each of them in order, so the request must
  pass all of them. `guards: ["user", "admin"]` means "logged in and admin", not "user or admin".
</Info>

→ [Protected Routes](/en/api-development/authentication/protected-routes)

</Accordion>
</AccordionGroup>

## Response Format

<AccordionGroup>
<Accordion title="How do I customize API responses?">

**Default response:**

```typescript
@api({ httpMethod: "GET" })
async getUser(id: number): Promise<UserSubsetMapping["A"]> {
  return this.findById("A", id);
}

// Response:
// {
//   "id": 1,
//   "name": "John",
//   "email": "john@example.com"
// }
```

**Custom response:**

```typescript
@api({ httpMethod: "GET" })
async getUserWithStats(id: number): Promise<{
  user: UserSubsetMapping["A"];
  stats: { postCount: number };
}> {
  const user = await this.findById("A", id);
  const { postCount } = await this.getPuri("r")
    .table("posts")
    .select({ postCount: Puri.count() })
    .where("posts.user_id", id)
    .first();

  return {
    user,
    stats: { postCount },
  };
}
```

**Setting headers:**

```typescript
@api({ httpMethod: "GET", contentType: "application/octet-stream" })
async downloadReport(id: number): Promise<Buffer> {
  const { reply } = Sonamu.getContext();
  reply.header("Content-Disposition", `attachment; filename="report-${id}.pdf"`);

  return buildReportPdf(id); // Your own function that returns a Buffer
}
```

</Accordion>

<Accordion title="How do I return paginated responses?">

**Using ListResult:**

```typescript
@api({ httpMethod: "GET" })
async listUsers(
  listParams: UserListParams,
): Promise<ListResult<UserListParams, UserSubsetMapping["A"]>> {
  // ListResult = { rows: T[], total: number }
  return this.findMany("A", listParams);
}

// Response:
// {
//   "rows": [
//     { "id": 1, "name": "John" },
//     { "id": 2, "name": "Jane" }
//   ],
//   "total": 100
// }
```

</Accordion>
</AccordionGroup>

## Frontend Integration

<AccordionGroup>
<Accordion title="How do I use auto-generated client code?">

**Service files auto-generated:**

When Model files change, Sonamu regenerates `services.generated.ts` in each sync target. Each Model gets a `{Entity}Service` namespace with a fetch function and, for `tanstack-query` clients, a hook.

```typescript
// web/src/services/services.generated.ts (auto-generated)
export namespace UserService {
  export async function getUser<T extends UserSubsetKey>(
    subset: T,
    id: number,
  ): Promise<UserSubsetMapping[T]> {
    return fetch({
      method: "GET",
      url: `/api/user/findById?${qs.stringify({ subset, id })}`,
    });
  }

  export const useUser = <T extends UserSubsetKey>(
    subset: T,
    id: number,
    options?: { enabled?: boolean },
  ) => useRefreshable(useQuery({ ...getUserQueryOptions(subset, id), ...options }));

  // ...
}
```

**Using in React:**

```typescript
import { useEffect, useState } from "react";
import { UserService } from "@/services/services.generated";
import type { UserSubsetMapping } from "@/services/sonamu.generated";

function UserProfile({ userId }: { userId: number }) {
  const [user, setUser] = useState<UserSubsetMapping["A"] | null>(null);

  useEffect(() => {
    UserService.getUser("A", userId).then(setUser);
  }, [userId]);

  return <div>{user?.name}</div>;
}
```

**Using TanStack Query hooks:**

```typescript
import { UserService } from "@/services/services.generated";

function UserProfile({ userId }: { userId: number }) {
  const { data: user, error, isLoading } = UserService.useUser("A", userId);

  if (isLoading) return <div>Loading...</div>;
  if (error) return <div>Error: {error.message}</div>;

  return <div>{user?.name}</div>;
}
```
