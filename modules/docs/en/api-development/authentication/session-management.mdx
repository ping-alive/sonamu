Sonamu authentication is built on [better-auth](https://www.better-auth.com/), and better-auth owns
the session lifecycle: it issues the session cookie, stores sessions, refreshes and expires them, and
revokes them. This page covers how those sessions reach your APIs and how to configure and control
them through `server.auth`.

<Info>
  Sonamu has no separate session plugin. Configure everything on this page in `server.auth`, which
  accepts better-auth options. See [Authentication Setup](/en/api-development/authentication/setup)
  first if authentication is not enabled yet.
</Info>

## How Sessions Work

1. A client signs in through a better-auth endpoint such as `POST /api/auth/sign-in/email`.
2. better-auth creates a row in the `sessions` table (through Sonamu's Knex adapter) and sets a
   signed session cookie.
3. For every HTTP and WebSocket request, Sonamu calls better-auth's `getSession` with the request
   headers and passes the result to the context as `user` and `session`.
4. Signing out or revoking a session deletes it, and the next request resolves `user` and `session`
   as `null`.

The `sessions` table is one of the entities created by `pnpm sonamu auth generate`:

| Column       | Description                                    |
| ------------ | ---------------------------------------------- |
| `id`         | Session ID                                     |
| `token`      | Session token stored in the cookie             |
| `user_id`    | Owner of the session                           |
| `expires_at` | Expiration time                                |
| `ip_address` | Client IP at sign-in                           |
| `user_agent` | Client user agent at sign-in                   |
| `created_at` | Creation time                                  |
| `updated_at` | Last refresh time                              |

## Reading the Session in APIs

`user` and `session` are part of the default context. Both are `null` when the request is
unauthenticated or when `server.auth` is not configured.

```typescript
import { BaseModelClass, Sonamu, UnauthorizedException, api } from "sonamu";

class UserModelClass extends BaseModelClass {
  @api({ httpMethod: "GET" })
  async getMySession() {
    const { user, session } = Sonamu.getContext();
    if (!user || !session) {
      throw new UnauthorizedException("Login required");
    }

    return {
      userId: user.id,
      expiresAt: session.expiresAt,
      ipAddress: session.ipAddress,
    };
  }
}
```

The session object uses better-auth's field names (`expiresAt`, `userId`, `ipAddress`), not the
snake_case column names.

To require a login declaratively, use guards and implement the check in `guardHandler`. See
[Protected Routes](/en/api-development/authentication/protected-routes).

## Configuring Session Lifetime

Set session options under `server.auth.session`. All values are in seconds.

```typescript
// sonamu.config.ts
export default defineConfig({
  server: {
    auth: {
      emailAndPassword: { enabled: true },
      session: {
        expiresIn: 60 * 60 * 24 * 7, // Session lifetime (default: 7 days)
        updateAge: 60 * 60 * 24, // Extend the expiration at most once per day (default: 1 day)
        freshAge: 60 * 60 * 24, // Age at which a session still counts as "fresh" (default: 1 day)
      },
    },
  },
});
```

| Option                  | Default  | Description                                                                         |
| ----------------------- | -------- | ----------------------------------------------------------------------------------- |
| `expiresIn`             | 7 days   | Lifetime of a session                                                               |
| `updateAge`             | 1 day    | When a session is used after this interval, its expiration is extended (sliding)    |
| `disableSessionRefresh` | `false`  | Disable sliding expiration; sessions expire `expiresIn` after sign-in               |
| `freshAge`              | 1 day    | Sessions older than this are not "fresh" for sensitive operations                   |
| `cookieCache`           | disabled | Cache the session in a signed cookie to skip the database lookup                    |

**Fixed expiration**: set `disableSessionRefresh: true` so the session always ends `expiresIn` after
sign-in.

**Sliding expiration** (default): every use after `updateAge` extends the session by `expiresIn`.
Set `updateAge: 0` to extend on every request.

### Remember Me

`signIn.email` accepts `rememberMe` (default `true`). With `rememberMe: false`, better-auth issues a
session cookie that is not persisted, so the user is signed out when the browser closes.

```typescript
await authClient.signIn.email({
  email: "user@example.com",
  password: "password123",
  rememberMe: false,
});
```

## Reducing Session Lookups

Sonamu resolves the session on every request. Two better-auth options reduce database load.

**Cookie cache** stores a signed copy of the session in a short-lived cookie:

```typescript
server: {
  auth: {
    session: {
      cookieCache: {
        enabled: true,
        maxAge: 5 * 60, // 5 minutes
      },
    },
  },
},
```

<Warning>
  With the cookie cache enabled, a revoked session can remain valid on other devices until the cached
  cookie expires (`maxAge`). Keep `maxAge` short.
</Warning>

**Secondary storage** keeps sessions in a key-value store such as Redis. Implement `get`, `set`, and
`delete`; `set` receives the TTL in seconds.

```typescript
import { createClient } from "redis";

const redis = createClient({ url: process.env.REDIS_URL });
await redis.connect();

export default defineConfig({
  server: {
    auth: {
      secondaryStorage: {
        get: (key) => redis.get(key),
        set: async (key, value, ttl) => {
          if (ttl) await redis.set(key, value, { EX: ttl });
          else await redis.set(key, value);
        },
        delete: async (key) => {
          await redis.del(key);
        },
      },
      session: {
        storeSessionInDatabase: true, // Keep rows in the sessions table as well
      },
    },
  },
});
```

When secondary storage is set, better-auth stores sessions only there unless
`storeSessionInDatabase` is `true`, and always reads from it.

## Listing and Revoking Sessions

### From the Client

```typescript
import { createAuthClient } from "better-auth/react";

export const authClient = createAuthClient({
  baseURL: "http://localhost:34900/api/auth",
});

// Sign out of the current session
await authClient.signOut();

// List the current user's active sessions
const { data: sessions } = await authClient.listSessions();

// Revoke one session by token
await authClient.revokeSession({ token: sessions[0].token });

// Revoke every session except the current one
await authClient.revokeOtherSessions();

// Revoke every session, including the current one
await authClient.revokeSessions();
```

### From an API

`Sonamu.auth` is the better-auth instance. Its server API takes the request headers; convert
Fastify headers with `convertFastifyHeadersToStandard`.

```typescript
import {
  BaseModelClass,
  Sonamu,
  UnauthorizedException,
  api,
  convertFastifyHeadersToStandard,
} from "sonamu";

class AuthModelClass extends BaseModelClass {
  @api({ httpMethod: "POST", guards: ["user"] })
  async logoutOtherDevices(): Promise<{ success: boolean }> {
    const { request, user } = Sonamu.getContext();
    if (!user) {
      throw new UnauthorizedException("Login required");
    }

    const headers = convertFastifyHeadersToStandard(request.headers);
    await Sonamu.auth.api.revokeOtherSessions({ headers });

    return { success: true };
  }

  @api({ httpMethod: "GET", guards: ["user"] })
  async mySessions() {
    const { request } = Sonamu.getContext();
    const headers = convertFastifyHeadersToStandard(request.headers);
    return Sonamu.auth.api.listSessions({ headers });
  }
}
```

<Note>`Sonamu.auth` throws if `server.auth` is not configured.</Note>

### Limiting Concurrent Logins

To keep a single active session per user, revoke the other sessions right after a successful
sign-in, for example by calling `authClient.revokeOtherSessions()` on the client after
`signIn.email` resolves.

## Cleaning Up Expired Sessions

Expired sessions are rejected, but their rows stay in the `sessions` table. Delete them periodically
with a scheduled workflow.

```typescript
// src/application/auth/cleanup-sessions.workflow.ts
import { BaseModel, workflow } from "sonamu";

export const cleanupExpiredSessions = workflow(
  {
    name: "cleanup_expired_sessions",
    schedules: [{ expression: "0 0 * * *" }], // Every day at midnight
  },
  async ({ logger }) => {
    const deleted = await BaseModel.getPuri("w")
      .table("sessions")
      .where("expires_at", "<", new Date())
      .delete();

    logger.info(`Deleted ${deleted} expired sessions`);
  },
);
```

## Cautions

<Warning>
  1. Set better-auth's `secret` (or the `BETTER_AUTH_SECRET` environment variable) in production;
  it signs session cookies.
  2. Set `baseURL` and `trustedOrigins` to the URLs your clients actually use.
  3. Serve production traffic over HTTPS so better-auth can issue secure cookies.
  4. Keep `cookieCache.maxAge` short if you rely on revoking sessions.
</Warning>
