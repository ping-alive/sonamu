이 가이드에서는 Sonamu UI를 사용하여 `Post` 엔티티를 만들고, 데이터베이스 테이블을 생성하며, 스캐폴딩으로 Model 파일을 자동 생성하는 방법을 알아봅니다.

## 전제 조건

- [빠른 시작](/ko/getting-started/quick-start) 가이드를 완료하고 개발 서버가 실행 중이어야 합니다.
- API 서버가 http://localhost:34900 에서 실행 중이어야 합니다.

<Tip>
  API 서버(`pnpm dev`)가 실행되면 Sonamu UI가 http://localhost:34900/sonamu-ui 에서 자동으로
  제공됩니다.
</Tip>

## 1단계: Sonamu UI 접속

브라우저에서 http://localhost:34900/sonamu-ui 로 접속합니다.

<Frame caption="Sonamu UI 메인 화면 (Entity, Migration, Scaffolding 탭)">
  <img
    src="/images/sonamuUI1.png"
    alt="Sonamu UI 메인 화면"
    style={{ width: "100%", borderRadius: "0.75rem" }}
  />
</Frame>

Sonamu UI는 엔티티를 시각적으로 관리할 수 있는 웹 인터페이스입니다. 여기서 다음 작업을 수행할 수 있습니다:

- 엔티티 생성 및 편집
- 프롭 추가/수정/삭제
- 관계(Relation) 정의
- Enum 타입 관리
- Subset 정의
- 마이그레이션 생성 및 실행
- 스캐폴딩 (Model 파일 자동 생성)

## 2단계: 새 엔티티 생성

<Steps>
<Step title="Entity 탭 클릭">
Sonamu UI 상단 메뉴에서 **Entity** 탭을 클릭하여 현재 존재하는 엔티티를 확인합니다.

<Frame caption="Entity 탭 화면">
  <img src="/images/sonamuUI1.png" alt="Entity 탭" style={{width: '100%', borderRadius: '0.75rem'}} />
</Frame>
</Step>

<Step title="New Entity 버튼 클릭">
좌측 사이드바 하단에 있는 **New Entity** 버튼을 클릭합니다.

<Frame caption="엔티티 생성 모달 창">
  <img src="/images/sonamuUI-create-entity.png" alt="엔티티 생성 모달" style={{width: '100%', borderRadius: '0.75rem'}} />
</Frame>
</Step>

<Step title="기본 정보 입력 및 생성">
새 엔티티의 기본 정보를 입력하고 **Create** 버튼을 클릭합니다:

- **Entity ID**: `Post` (대문자로 시작, 단수형)
- **Table Name**: `posts` (소문자, 복수형)
- **Title**: `게시글`

<Frame caption="Create 버튼 클릭 후 생성된 Post 엔티티 화면">
  <img
    src="/images/sonamuUI-created-entity.png"

  />
</Frame>

<Note>
**Entity ID**는 TypeScript 클래스명으로 사용되며, **Table Name**은 실제 데이터베이스 테이블명입니다.
</Note>
</Step>
</Steps>

## 3단계: 프롭 정의

이제 `Post` 엔티티에 프롭들을 추가합니다:

<Steps>
<Step title="기본 프롭 추가">

**Add a prop** 버튼을 클릭하여 다음 프롭들을 추가합니다:

| 프롭명       | 타입    | 설명     | 옵션                            |
| ------------ | ------- | -------- | ------------------------------- |
| `id`         | integer | ID       | Primary Key                     |
| `created_at` | date    | 생성일시 | DB Default: `CURRENT_TIMESTAMP` |
| `title`      | string  | 제목     | Length: 255                     |
| `content`    | string  | 내용     | -                               |
| `author`     | string  | 작성자   | Length: 100                     |
| `view_count` | integer | 조회수   | DB Default: `0`                 |

<Accordion title="각 프롭 설정 방법">

**id 프롭**

- Name: `id`
- Type: `integer`
- Description: `ID`

**created_at 프롭**

- Name: `created_at`
- Type: `date`
- Description: `생성일시`
- DB Default: `CURRENT_TIMESTAMP`

**title 프롭**

- Name: `title`
- Type: `string`
- Description: `제목`
- Length: `255`

**content 프롭**

- Name: `content`
- Type: `string`
- Description: `내용`
- Length: 빈칸 (TEXT 타입으로 생성됨)

**author 프롭**

- Name: `author`
- Type: `string`
- Description: `작성자`
- Length: `100`

**view_count 프롭**

- Name: `view_count`
- Type: `integer`
- Description: `조회수`
- DB Default: `0`

</Accordion>

<Frame caption="프롭 추가 UI (Add a prop 버튼과 모든 프롭이 추가된 프롭 리스트)">

</Step>

<Step title="Subset 정의">

**Subsets** 섹션에서 데이터 조회 형태를 정의합니다:

- **Subset A** (Admin): `id`, `created_at`, `title`, `content`, `author`, `view_count` - 전체 정보
- **Subset P** (Public): `id`, `title`, `author`, `created_at` - 공개 정보
- **Subset SS** (Secure Short): `id`, `title`, `author` - 요약 정보

<Frame caption="Subset 편집 화면 (Subset A, P, SS가 정의된 상태)">

  [Subset 가이드](/ko/database/subsets/what-are-subsets)를 참고하세요.

</Step>

- `view_count-desc`: 조회수 높은순

**PostSearchField**

- `id`: ID
- `title`: 제목

## 4단계: 데이터베이스 마이그레이션

이제 엔티티 정의를 데이터베이스에 반영해야 합니다.

<Steps>
<Step title="Migration 탭으로 이동">
Sonamu UI에서 **Migration** 탭을 클릭합니다. 상단에는 비교·생성 영역이, 하단에는 DB별 마이그레이션 상태 매트릭스가 표시됩니다.
</Step>

<Step title="마이그레이션 생성">
**마이그레이션 생성** 버튼을 클릭하면 새로운 마이그레이션 Code File이 자동 생성됩니다.

생성된 파일 목록의 첫 번째 버튼은 코드를 화면에 펼치고, 그 옆 IDE 버튼은 에디터 선택 메뉴를 엽니다. IDE 버튼을 누르고 **Cursor**를 선택하면 해당 마이그레이션 파일이 열립니다. 파일 내용은 다음과 같습니다:

<Frame caption="Cursor에서 열린 마이그레이션 파일">
  <img src="/images/sonamuUI-db-migration3.png" alt="Cursor에서 열린 마이그레이션 파일" style={{width: '100%', borderRadius: '0.75rem'}} />
</Frame>
</Step>

<Step title="마이그레이션 실행">
Migration 탭에서 pending 상태의 마이그레이션을 확인할 수 있습니다.

마이그레이션 상태 표의 헤더에서 적용할 DB를 선택한 후 **최신으로 적용**을 클릭하면 검토 창에서 migration targets를 확인할 수 있습니다.

검토 창의 **적용 전 shadow 검증**을 필요에 따라 켜고 적용 버튼을 누릅니다. Shadow 검증에 성공하면 선택한 DB에 마이그레이션을 적용해 테이블을 생성합니다.

## 7단계: 프론트엔드 Service 자동 생성

API를 작성하면 프론트엔드 Service 파일이 자동으로 생성됩니다.

<Frame caption="📸 필요: VS Code에서 web/src/services/PostService.ts 파일이 생성된 화면"></Frame>

```typescript title="web/src/services/PostService.ts (자동 생성)"
export class PostService {
  static async findById(subset: PostSubsetKey, id: number) {
    const res = await axios.get(`/api/posts/${id}`, {
      params: { subset },
    });
    return res.data;
  }

  static async findMany(subset: PostSubsetKey, params?: PostListParams) {
    const res = await axios.get("/api/posts", {
      params: { subset, ...params },
    });
    return res.data;
  }

  static async save(params: PostSaveParams) {
    const res = await axios.post("/api/posts", params);
    return res.data;
  }

  static async del(id: number) {
    await axios.delete(`/api/posts/${id}`);
  }
}
```

## 8단계: API 테스트

이제 API가 정상적으로 작동하는지 테스트해봅니다.

### REST Client로 테스트

<CodeGroup>
```bash title="게시글 생성 (POST)"
curl -X POST http://localhost:34900/api/posts \
  -H "Content-Type: application/json" \
  -d '{
    "title": "첫 번째 게시글",
    "content": "Sonamu로 만든 첫 번째 게시글입니다.",
    "author": "홍길동"
  }'
```

```bash title="게시글 목록 조회 (GET)"
curl http://localhost:34900/api/posts?subset=A
```

```bash title="게시글 상세 조회 (GET)"
curl http://localhost:34900/api/posts/1?subset=A
```

```bash title="게시글 삭제 (DELETE)"
curl -X DELETE http://localhost:34900/api/posts/1
```

</CodeGroup>

### 브라우저에서 테스트

http://localhost:34900/api/posts?subset=A 로 접속하여 JSON 응답을 확인합니다.

<Frame caption="📸 필요: 브라우저에서 API 응답 JSON 화면 (게시글 목록 데이터)"></Frame>

## 완성! 🎉

축하합니다! 첫 번째 엔티티를 성공적으로 만들었습니다.

지금까지 다음 작업을 완료했습니다:

- ✅ Sonamu UI로 엔티티 정의
- ✅ 데이터베이스 테이블 생성
- ✅ 타입 및 스키마 자동 생성
- ✅ 스캐폴딩으로 Model 및 Test 파일 자동 생성
- ✅ REST API 자동 생성
- ✅ 프론트엔드 Service 자동 생성
- ✅ API 테스트

<Warning>
  **스캐폴딩의 장점**

스캐폴딩을 사용하면:

- Model 파일을 직접 작성할 필요 없이 기본 CRUD API가 자동 생성됩니다
- 테스트 파일 템플릿도 함께 생성되어 테스트 작성이 쉬워집니다
- 프로젝트의 일관된 코드 스타일을 유지할 수 있습니다
- 생성된 코드는 언제든지 수정하여 비즈니스 로직을 추가할 수 있습니다
</Warning>
