---
title: "세션 관리"
description: "Sonamu에서 better-auth 세션의 생명주기 관리"
---

Sonamu의 인증은 [better-auth](https://www.better-auth.com/)를 기반으로 하며, 세션의 생명주기는
better-auth가 관리합니다. better-auth가 세션 쿠키를 발급하고, 세션을 저장하고, 갱신·만료·폐기합니다. 이
페이지에서는 세션이 API에 전달되는 방식과 `server.auth`로 세션을 설정하고 제어하는 방법을 다룹니다.

<Info>
  Sonamu에는 별도의 세션 플러그인이 없습니다. 이 페이지의 설정은 모두 better-auth 옵션을 받는
  `server.auth`에서 합니다. 아직 인증을 켜지 않았다면 먼저
  [인증 설정](/ko/api-development/authentication/setup)을 참고하세요.
</Info>

## 세션 동작 방식

1. 클라이언트가 `POST /api/auth/sign-in/email` 같은 better-auth 엔드포인트로 로그인합니다.
2. better-auth가 Sonamu의 Knex 어댑터를 통해 `sessions` 테이블에 행을 만들고 서명된 세션 쿠키를
   설정합니다.
3. Sonamu는 모든 HTTP·WebSocket 요청마다 요청 헤더로 better-auth의 `getSession`을 호출하고, 그 결과를
   Context의 `user`와 `session`으로 전달합니다.
4. 로그아웃하거나 세션을 폐기하면 세션이 삭제되고, 다음 요청부터 `user`와 `session`은 `null`이 됩니다.

`sessions` 테이블은 `pnpm sonamu auth generate`가 만드는 엔티티 중 하나입니다:

| 컬럼         | 설명                         |
| ------------ | ---------------------------- |
| `id`         | 세션 ID                      |
| `token`      | 쿠키에 저장되는 세션 토큰    |
| `user_id`    | 세션 소유자                  |
| `expires_at` | 만료 시각                    |
| `ip_address` | 로그인 시 클라이언트 IP      |
| `user_agent` | 로그인 시 클라이언트 User-Agent |
| `created_at` | 생성 시각                    |
| `updated_at` | 마지막 갱신 시각             |

## API에서 세션 읽기

`user`와 `session`은 기본 Context에 포함됩니다. 인증되지 않은 요청이거나 `server.auth`를 설정하지
않았다면 둘 다 `null`입니다.

```typescript
import { BaseModelClass, Sonamu, UnauthorizedException, api } from "sonamu";

class UserModelClass extends BaseModelClass {
  @api({ httpMethod: "GET" })
  async getMySession() {
    const { user, session } = Sonamu.getContext();
    if (!user || !session) {
      throw new UnauthorizedException("Login required");
    }

    return {
      userId: user.id,
      expiresAt: session.expiresAt,
      ipAddress: session.ipAddress,
    };
  }
}
```

session 객체는 snake_case 컬럼 이름이 아니라 better-auth의 필드 이름(`expiresAt`, `userId`,
`ipAddress`)을 씁니다.

로그인을 선언적으로 요구하려면 guards를 쓰고 `guardHandler`에서 검사를 구현하세요.
[보호된 라우트](/ko/api-development/authentication/protected-routes)를 참고하세요.

## 세션 수명 설정

세션 옵션은 `server.auth.session`에 지정합니다. 모든 값의 단위는 초입니다.

```typescript
// sonamu.config.ts
export default defineConfig({
  server: {
    auth: {
      emailAndPassword: { enabled: true },
      session: {
        expiresIn: 60 * 60 * 24 * 7, // 세션 수명 (기본: 7일)
        updateAge: 60 * 60 * 24, // 만료 시각 연장은 최대 하루에 한 번 (기본: 1일)
        freshAge: 60 * 60 * 24, // "fresh" 세션으로 보는 나이 (기본: 1일)
      },
    },
  },
});
```

| 옵션                    | 기본값  | 설명                                                                 |
| ----------------------- | ------- | -------------------------------------------------------------------- |
| `expiresIn`             | 7일     | 세션 수명                                                            |
| `updateAge`             | 1일     | 이 간격이 지난 뒤 세션을 사용하면 만료 시각을 연장합니다(sliding)    |
| `disableSessionRefresh` | `false` | sliding 만료를 끄고, 로그인 후 `expiresIn`이 지나면 만료합니다       |
| `freshAge`              | 1일     | 이보다 오래된 세션은 민감한 작업에서 "fresh"로 보지 않습니다         |
| `cookieCache`           | 꺼짐    | 서명된 쿠키에 세션을 캐시해 데이터베이스 조회를 건너뜁니다           |

**고정 만료**: `disableSessionRefresh: true`로 설정하면 세션은 로그인 후 항상 `expiresIn`이 지나면
만료됩니다.

**Sliding 만료**(기본값): `updateAge`가 지난 뒤 사용할 때마다 세션이 `expiresIn`만큼 연장됩니다.
`updateAge: 0`이면 요청마다 연장합니다.

### 로그인 상태 유지 (Remember Me)

`signIn.email`은 `rememberMe`(기본 `true`)를 받습니다. `rememberMe: false`이면 better-auth가 유지되지
않는 세션 쿠키를 발급하므로 브라우저를 닫으면 로그아웃됩니다.

```typescript
await authClient.signIn.email({
  email: "user@example.com",
  password: "password123",
  rememberMe: false,
});
```

## 세션 조회 줄이기

Sonamu는 요청마다 세션을 조회합니다. 다음 두 better-auth 옵션으로 데이터베이스 부하를 줄일 수
있습니다.

**쿠키 캐시**는 서명된 세션 사본을 수명이 짧은 쿠키에 저장합니다:

```typescript
server: {
  auth: {
    session: {
      cookieCache: {
        enabled: true,
        maxAge: 5 * 60, // 5분
      },
    },
  },
},
```

<Warning>
  쿠키 캐시를 켜면 폐기한 세션이 다른 기기에서 캐시 쿠키가 만료될 때(`maxAge`)까지 유효할 수
  있습니다. `maxAge`는 짧게 유지하세요.
</Warning>

**보조 저장소(secondary storage)**는 Redis 같은 key-value 저장소에 세션을 둡니다. `get`, `set`,
`delete`를 구현하며, `set`은 TTL을 초 단위로 받습니다.

```typescript
import { createClient } from "redis";

const redis = createClient({ url: process.env.REDIS_URL });
await redis.connect();

export default defineConfig({
  server: {
    auth: {
      secondaryStorage: {
        get: (key) => redis.get(key),
        set: async (key, value, ttl) => {
          if (ttl) await redis.set(key, value, { EX: ttl });
          else await redis.set(key, value);
        },
        delete: async (key) => {
          await redis.del(key);
        },
      },
      session: {
        storeSessionInDatabase: true, // sessions 테이블에도 행을 유지
      },
    },
  },
});
```

보조 저장소를 설정하면 better-auth는 `storeSessionInDatabase`가 `true`가 아닌 한 세션을 보조 저장소에만
저장하며, 읽기는 항상 보조 저장소에서 합니다.

## 세션 조회와 폐기

### 클라이언트에서

```typescript
import { createAuthClient } from "better-auth/react";

export const authClient = createAuthClient({
  baseURL: "http://localhost:34900/api/auth",
});

// 현재 세션 로그아웃
await authClient.signOut();

// 현재 사용자의 활성 세션 목록
const { data: sessions } = await authClient.listSessions();

// 토큰으로 세션 하나 폐기
await authClient.revokeSession({ token: sessions[0].token });

// 현재 세션을 제외한 모든 세션 폐기
await authClient.revokeOtherSessions();

// 현재 세션을 포함한 모든 세션 폐기
await authClient.revokeSessions();
```

### API에서

`Sonamu.auth`는 better-auth 인스턴스입니다. 서버 API는 요청 헤더를 받으므로 Fastify 헤더를
`convertFastifyHeadersToStandard`로 변환해 넘깁니다.

```typescript
import {
  BaseModelClass,
  Sonamu,
  UnauthorizedException,
  api,
  convertFastifyHeadersToStandard,
} from "sonamu";

class AuthModelClass extends BaseModelClass {
  @api({ httpMethod: "POST", guards: ["user"] })
  async logoutOtherDevices(): Promise<{ success: boolean }> {
    const { request, user } = Sonamu.getContext();
    if (!user) {
      throw new UnauthorizedException("Login required");
    }

    const headers = convertFastifyHeadersToStandard(request.headers);
    await Sonamu.auth.api.revokeOtherSessions({ headers });

    return { success: true };
  }

  @api({ httpMethod: "GET", guards: ["user"] })
  async mySessions() {
    const { request } = Sonamu.getContext();
    const headers = convertFastifyHeadersToStandard(request.headers);
    return Sonamu.auth.api.listSessions({ headers });
  }
}
```

<Note>`server.auth`를 설정하지 않았다면 `Sonamu.auth`는 예외를 던집니다.</Note>

### 동시 로그인 제한

사용자당 활성 세션을 하나로 유지하려면 로그인에 성공한 직후 다른 세션을 폐기하세요. 예를 들어
클라이언트에서 `signIn.email`이 resolve된 뒤 `authClient.revokeOtherSessions()`를 호출합니다.

## 만료된 세션 정리

만료된 세션은 거부되지만 `sessions` 테이블의 행은 남습니다. 스케줄 workflow로 주기적으로 삭제하세요.

```typescript
// src/application/auth/cleanup-sessions.workflow.ts
import { BaseModel, workflow } from "sonamu";

export const cleanupExpiredSessions = workflow(
  {
    name: "cleanup_expired_sessions",
    schedules: [{ expression: "0 0 * * *" }], // 매일 자정
  },
  async ({ logger }) => {
    const deleted = await BaseModel.getPuri("w")
      .table("sessions")
      .where("expires_at", "<", new Date())
      .delete();

    logger.info(`Deleted ${deleted} expired sessions`);
  },
);
```

## 주의사항

<Warning>
  1. 프로덕션에서는 better-auth의 `secret`(또는 `BETTER_AUTH_SECRET` 환경 변수)을 설정하세요. 세션
  쿠키 서명에 쓰입니다.
  2. `baseURL`과 `trustedOrigins`를 클라이언트가 실제로 쓰는 URL로 설정하세요.
  3. better-auth가 secure 쿠키를 발급할 수 있도록 프로덕션은 HTTPS로 서비스하세요.
  4. 세션 폐기에 의존한다면 `cookieCache.maxAge`를 짧게 유지하세요.
</Warning>
