---
title: "migrate"
description: "데이터베이스 마이그레이션 관리하기"
---

`pnpm sonamu migrate` 명령어는 데이터베이스 스키마 변경을 관리합니다. Sonamu는 Entity 정의와
데이터베이스 스키마를 비교해 차이로부터 Knex 마이그레이션 파일을 생성하고, 선택한 데이터베이스에
적용합니다.

## 기본 개념

- **Entity 기반**: `migrate generate`가 Entity와 데이터베이스의 차이로 마이그레이션 코드를 작성합니다
- **Git으로 관리하는 파일**: 생성된 마이그레이션은 `src/migrations/`에 저장되며 다른 소스 파일처럼
  커밋합니다
- **명시적 실행**: 데이터베이스를 바꾸는 명령은 `--execute`를 주지 않으면 dry-run입니다
- **다중 데이터베이스**: Sonamu DB preset(`development`, `staging`, `production`, `test`, `fixture`)이
  각각 마이그레이션 대상입니다

## 명령어

| 명령어                                              | 설명                                                        |
| --------------------------------------------------- | ----------------------------------------------------------- |
| `migrate status`                                    | 커넥션별 적용 버전과 대기 중인 마이그레이션 표시            |
| `migrate generate`                                  | Entity 변경에 대한 마이그레이션 파일을 `src/migrations/`에 작성 |
| `migrate run [--execute]`                           | 현재 `NODE_ENV`의 데이터베이스에 대기 중인 마이그레이션 적용 |
| `migrate apply TARGET... [--execute]`               | 지정한 대상들에 대기 중인 마이그레이션 적용                 |
| `migrate preview TARGET [--action apply\|rollback]` | apply나 rollback이 실행할 마이그레이션 파일 표시            |
| `migrate code TARGET`                               | 대상과 비교해 생성될 마이그레이션 코드 표시                 |
| `migrate connections`                               | 설정된 마이그레이션 커넥션 목록                             |
| `migrate shadow test\|fixture [--execute]`          | 데이터베이스의 임시 복사본에 대기 중인 마이그레이션 적용    |
| `migrate rollback TARGET [--execute]`               | 한 대상에서 마지막으로 적용된 batch 롤백                    |

`TARGET`은 `development`, `staging`, `production`, `fixture`, `test` 중 하나입니다.

### status - 상태 확인

```bash
pnpm sonamu migrate status
```

결과에는 커넥션마다 현재 버전과 대기 중인 마이그레이션 파일이 나옵니다. 아직 마이그레이션 파일이 없는
Entity 변경에 대해 Sonamu가 생성할 코드도 **prepared migrations**로 함께 표시됩니다.

### generate - 마이그레이션 파일 생성

```bash
pnpm sonamu migrate generate
```

- 이름 인자를 받지 않습니다. 파일 이름은 변경 내용에서 정해지며, 예를 들면
  `20240116103045_create__posts.ts`나 `20240116103046_alter_users_add1.ts`입니다.
- 한 번에 생성되는 파일은 타임스탬프가 1초씩 차이 나므로 순서가 유지됩니다.
- 대기 중인 마이그레이션이 없는 커넥션과 비교해 생성합니다. 모든 커넥션에 대기 중인 마이그레이션이
  있으면 `MIGRATION_NOT_READY`로 실패하므로 먼저 적용하세요.

### run - 현재 환경에 적용

```bash
# 개발 (NODE_ENV 미설정 또는 development)
pnpm sonamu migrate run --execute

# 프로덕션
NODE_ENV=production pnpm sonamu migrate run --execute --force-reason CHANGE_REQUEST
```

- `run`은 현재 `NODE_ENV`의 preset에 대기 중인 마이그레이션을 적용합니다. `NODE_ENV=test`이면
  `test`와 `fixture`에 모두 적용합니다.
- `--execute`가 없으면 dry-run이며 아무것도 바꾸지 않습니다. 실행 계획은 `migrate preview TARGET`으로
  확인하세요.
- `run`은 마이그레이션을 생성하지 않습니다. 먼저 `migrate generate`를 실행하세요.
- `NODE_ENV=production`에서는 `--force-reason`이 필요합니다.

### apply - 대상을 지정해 적용

```bash
# 먼저 계획 확인
pnpm sonamu migrate preview development --action apply

# 여러 대상에 순서대로 적용
pnpm sonamu migrate apply development test --execute

# 프로덕션은 사유 필요
pnpm sonamu migrate apply production --execute --force-reason CHANGE_REQUEST
```

TTY에서 대상을 생략하면 대상 선택 프롬프트가 열립니다.

### shadow - 임시 복사본에서 검증

```bash
pnpm sonamu migrate shadow test --execute
```

Sonamu는 `test`(또는 `fixture`) 데이터베이스를 템플릿으로 `<database>__migration_shadow`를 만들고,
대기 중인 마이그레이션을 적용한 뒤 삭제합니다. `test`와 `fixture`만 받습니다.

### rollback - 마지막 batch 롤백

```bash
# 롤백될 파일 확인
pnpm sonamu migrate preview development --action rollback

# 마지막으로 적용된 batch 롤백
pnpm sonamu migrate rollback development --execute
```

대상 인자는 필수이며 `NODE_ENV`로 대신할 수 없습니다. `production` 롤백에도 `--force-reason`이
필요합니다.

<Info>
  데이터베이스를 바꾸는 명령은 TTY에서 확인을 요청합니다. 비대화형 실행에서는 `--confirm`을
  추가하세요(예: `--execute --confirm`). 종료 코드와 JSON 출력은
  [CLI 레퍼런스](/ko/tools-and-cli/sonamu-cli/reference)를 참고하세요.
</Info>

## 마이그레이션 생성

### Entity 변경

Sonamu UI나 `.entity.json` 파일에서 Entity에 속성을 추가합니다:

```json title="src/application/user/user.entity.json"
{
  "id": "User",
  "table": "users",
  "props": [
    { "name": "id", "type": "integer", "desc": "ID" },
    { "name": "email", "type": "string", "length": 255, "desc": "이메일" },
    { "name": "phone", "type": "string", "length": 20, "nullable": true, "desc": "전화번호" }
  ]
}
```

```bash
# prepared migrations 확인
pnpm sonamu migrate status

# 마이그레이션 파일 작성
pnpm sonamu migrate generate

# 적용
pnpm sonamu migrate run --execute
```

### 마이그레이션 파일

생성된 마이그레이션 파일은 `src/migrations/` 디렉토리에 저장됩니다.

```typescript title="src/migrations/20240116103045_alter_users_add1.ts"
import type { Knex } from "knex";

export async function up(knex: Knex): Promise<void> {
  await knex.schema.alterTable("users", (table) => {
    table.string("phone", 20).nullable();
  });
}

export async function down(knex: Knex): Promise<void> {
  await knex.schema.alterTable("users", (table) => {
    table.dropColumn("phone");
  });
}
```

**구조**:

- `up()`: 마이그레이션 적용 (테이블 생성, 컬럼 추가 등)
- `down()`: 마이그레이션 롤백 (변경 사항 되돌리기)

## 지원하는 변경 사항

Sonamu가 감지해 마이그레이션을 생성하는 변경 사항:

| 변경 유형      | 설명             | 예시                            |
| -------------- | ---------------- | ------------------------------- |
| 테이블 생성    | 새 Entity 추가   | `Post` Entity 생성              |
| 컬럼 추가      | 새 속성 추가     | `phone` 필드 추가               |
| 컬럼 수정      | 타입/길이 변경   | `varchar(100)` → `varchar(255)` |
| 컬럼 삭제      | 속성 제거        | `deprecated_field` 삭제         |
| 인덱스 추가    | 인덱스 정의      | `indexes` 배열                  |
| 외래 키 추가   | 관계 정의        | `BelongsToOne` 관계             |

## 다중 데이터베이스 관리

### 데이터베이스 설정

```typescript title="sonamu.config.ts"
export default defineConfig({
  projectName: process.env.PROJECT_NAME ?? "MyApp",
  database: {
    database: "pg",
    defaultOptions: {
      pool: {
        min: 1,
        max: 10,
      },
    },
  },
  // ...
});
```

**마이그레이션 대상**:

- 각 DB preset(`development`, `staging`, `production`, `test`, `fixture`)이 대상입니다
- `*_readonly` preset은 마이그레이션 대상이 아닙니다
- 로컬 환경(`development`, `test`)에서는 모든 대상을 쓸 수 있고, `staging`과 `production`에서는 현재
  `NODE_ENV`의 preset만 쓸 수 있습니다

### 여러 데이터베이스에 적용

```bash
pnpm sonamu migrate apply development test fixture --execute
```

## 실전 워크플로우

### 1. Entity 변경

Sonamu UI나 `user.entity.json`에서 User Entity에 `profile_image`를 추가합니다.

### 2. 상태 확인

```bash
pnpm sonamu migrate status
```

prepared migrations에 새 컬럼이 포함됩니다.

### 3. 생성 및 적용

```bash
pnpm sonamu migrate generate
pnpm sonamu migrate run --execute
```

### 4. 코드 업데이트

```typescript title="user.model.ts"
class UserModelClass extends BaseModelClass {
  async updateProfileImage(userId: number, imageUrl: string) {
    await this.getPuri("w")
      .table("users")
      .where("id", userId)
      .update({ profile_image: imageUrl });
  }
}
```

## 고급 사용법 (프로그래밍 방식)

스크립트 안에서 마이그레이션이 필요하면 `Migrator` 클래스를 사용합니다.

### Migrator 클래스 사용

```typescript title="src/scripts/migration-tools.ts"
import { Migrator } from "sonamu";

const migrator = new Migrator();

// 특정 대상에 대기 중인 마이그레이션 적용
await migrator.apply(["test"]);

// 마지막 batch 롤백
await migrator.rollback(["development"]);

// 커넥션 하나의 상태 확인
const status = await migrator.getConnectionStatus("development");
console.log(status.currentVersion, status.pending);
```

`runAction("apply" | "rollback", targets)`는 하위 호환을 위해 남아 있지만 deprecated입니다.
`apply`나 `rollback`을 직접 호출하세요.

### 롤백 스크립트

```typescript title="src/scripts/rollback-migration.ts"
import { Migrator, Sonamu } from "sonamu";

await Sonamu.runScript(async () => {
  const migrator = new Migrator();

  console.log("Rolling back last migration batch...");
  await migrator.rollback(["development", "test"]);
  console.log("Rollback completed!");
});
```

<Warning>
  **데이터 손실 위험**: 롤백은 테이블이나 컬럼을 삭제할 수 있으므로 **프로덕션에서는 매우 신중하게**
  사용하세요.
</Warning>

## 문제 해결

### 마이그레이션 충돌

**문제**: 여러 개발자가 겹치는 변경에 대해 마이그레이션을 생성함

**해결**:

```bash
# 1. 최신 코드 받기
git pull

# 2. 다른 브랜치의 마이그레이션 적용
pnpm sonamu migrate run --execute

# 3. 남은 변경을 확인하고 다시 생성
pnpm sonamu migrate status
pnpm sonamu migrate generate
```

### 데이터베이스 연결 실패

**문제**: DB 연결 실패

```
Error: connect ECONNREFUSED 127.0.0.1:5432
```

**해결**:

```bash
# 1. PostgreSQL 실행 확인
psql -U postgres -c "\l"

# 2. Sonamu가 사용하는 커넥션 확인
pnpm sonamu migrate connections

# 3. 로컬 데이터베이스 시작 (생성된 프로젝트)
pnpm docker:up
```

### 마이그레이션 순서 오류

**문제**: 잘못된 순서로 적용됨

```
Error: Foreign key constraint violation
```

**해결**: 참조되는 테이블이 먼저 생성되어야 합니다. 롤백한 뒤 참조되는 테이블이 먼저 오도록 파일
타임스탬프를 조정하고 다시 적용하세요.

```bash
pnpm sonamu migrate rollback development --execute
# 이름 변경 예: 20240116110230_*.ts → 20240116110231_*.ts
pnpm sonamu migrate apply development --execute
```

## 베스트 프랙티스

### 1. 자주 적용하기

큰 변경을 쌓아 두지 말고 작은 단위로 생성하고 적용하세요.

### 2. 프로덕션 전 테스트

```bash
# 임시 복사본, 그다음 test 데이터베이스에서 검증
pnpm sonamu migrate shadow test --execute
pnpm sonamu migrate apply test --execute

# 적용 전에 프로덕션 계획 확인
pnpm sonamu migrate preview production --action apply
```

승인 워크플로우는 [프로덕션 승인](/ko/database/migrations/production-approval)을 참고하세요.

### 3. 백업 필수

```bash
# 프로덕션 마이그레이션 전 백업
pg_dump -U postgres myapp_prod > backup_$(date +%Y%m%d).sql

# 마이그레이션 적용
pnpm sonamu migrate apply production --execute --force-reason CHANGE_REQUEST
```

### 4. 롤백 가능성 고려

```typescript
// ✅ 롤백 가능 - down() 함수를 제대로 정의
export async function up(knex: Knex) {
  await knex.schema.alterTable("users", (table) => {
    table.string("phone").nullable();
  });
}

export async function down(knex: Knex) {
  await knex.schema.alterTable("users", (table) => {
    table.dropColumn("phone");
  });
}
```

### 5. Git으로 버전 관리

```bash
# 마이그레이션 파일을 Git에 커밋
git add src/migrations/
git commit -m "Add phone field to users table"

# 팀과 공유
git push
```
