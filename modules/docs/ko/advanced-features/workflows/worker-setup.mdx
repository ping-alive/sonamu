Workflow는 **백그라운드 작업**을 실행하는 시스템입니다. 이메일 발송, 데이터 처리, 스케줄 작업 등에 사용합니다.

## Tasks 설정

```typescript
// sonamu.config.ts
import { defineConfig } from "sonamu";

export default defineConfig({
  // ...
  tasks: {
    enableWorker: true, // Worker 활성화
    workerOptions: {
      concurrency: 4, // 동시 실행 수
      usePubSub: true, // Pub/Sub 사용
      listenDelay: 500, // 수신 지연 (ms)
    },
    contextProvider: async (baseContext) => {
      // Workflow에서 사용할 Context 설정
      return {
        ...baseContext,
        // 커스텀 데이터 추가 가능
      };
    },
  },
});
```

**옵션**:

- `enableWorker`: Worker 활성화 여부 (기본: `NODE_TYPE=daemon`일 때만 `true`)
- `workerOptions.concurrency`: 동시 실행 작업 수 (기본: CPU 코어 수 - 1)
- `workerOptions.usePubSub`: PostgreSQL LISTEN/NOTIFY 사용 (기본: true)
- `workerOptions.listenDelay`: Pub/Sub 메시지 수신 후 대기 시간 (기본: 500ms)
- `contextProvider`: Workflow 내에서 사용할 Context 생성 함수

## WorkflowManager

Sonamu는 `WorkflowManager`를 자동으로 생성하고 관리합니다. `Sonamu.workflows`로 접근할 수 있습니다.

```typescript
import { Sonamu } from "sonamu";

// Workflow 실행
const workflowManager = Sonamu.workflows;
const handle = await workflowManager.run(
  {
    name: "send_email",
    version: null,
  },
  { email: "user@example.com" },
);

// 결과 대기
const result = await handle.result();
```

## Worker 모드

### 1. Daemon 모드 (자동 활성화)

별도의 daemon 명령은 없습니다. `tasks.enableWorker`를 지정하지 않으면 Sonamu는 `NODE_TYPE=daemon`으로
시작한 프로세스에서만 Worker를 활성화합니다. Worker는 `Sonamu.init()`에서 생성되고 서버가 listen을 시작한
뒤 시작됩니다.

```bash
# 빌드된 서버를 daemon 노드로 시작하면 Worker도 함께 시작됨
NODE_TYPE=daemon pnpm sonamu start
```

어느 노드에서든 `enableWorker`를 명시하면 이 감지 대신 그 값을 사용합니다.

### 2. 별도 Worker 프로세스

```typescript
// src/worker.ts
import { Sonamu } from "sonamu";

async function startWorker() {
  await Sonamu.init(true, false);

  await Sonamu.workflows.startWorker();

  console.log("Worker started");

  // Graceful shutdown
  const shutdown = async () => {
    console.log("Stopping worker...");
    await Sonamu.workflows.stopWorker();
    process.exit(0);
  };

  process.on("SIGTERM", shutdown);
  process.on("SIGINT", shutdown);
}

startWorker();
```

```json
// package.json
{
  "scripts": {
    "worker": "tsx src/worker.ts",
    "worker:dev": "tsx watch src/worker.ts"
  }
}
```

```bash
# Worker 실행
pnpm worker
```

`startWorker()`는 `Sonamu.init()`이 만든 Worker만 시작합니다. `tasks.enableWorker: true`를 설정하거나
이 프로세스를 `NODE_TYPE=daemon`으로 실행하세요. 그렇지 않으면 Worker 없이 task 백엔드만 초기화됩니다.

### 3. API 서버 + Worker

```typescript
// sonamu.config.ts
export default defineConfig({
  tasks: {
    enableWorker: true, // API 서버에서도 Worker 실행
    workerOptions: {
      concurrency: 2, // API 서버는 적은 concurrency
    },
    contextProvider: async (baseContext) => baseContext,
  },
});
```

## 분산 Worker

여러 서버에서 Worker를 실행할 수 있습니다.

```typescript
// Server 1, 2, 3...
tasks: {
  enableWorker: true,
  workerOptions: {
    concurrency: 4,
    usePubSub: true,
  },
}
```

PostgreSQL이 작업 큐 역할을 하며, Pub/Sub으로 Worker 간 통신합니다.

## Context Provider

Workflow에서 사용할 Context를 커스터마이징합니다.

```typescript
// sonamu.config.ts
tasks: {
  enableWorker: true,
  contextProvider: async (defaultContext) => {
    // 시스템 사용자 조회
    const systemUser = await BaseModel.getPuri("r")
      .table("users")
      .select({ id: "users.id" })
      .where("users.email", "system@example.com")
      .first();

    return {
      ...defaultContext,
      systemUserId: systemUser?.id ?? null,
    };
  },
}
```

`systemUserId` 같은 커스텀 필드는 `ContextExtend`에 선언해야 타입이 맞습니다.

Workflow 함수 내에서 `Sonamu.getContext()`로 접근:

```typescript
import { workflow } from "sonamu";
import { Sonamu } from "sonamu";

export const myWorkflow = workflow({ name: "my_workflow" }, async ({ input, step }) => {
  const context = Sonamu.getContext();
  console.log(context.systemUserId);
});
```

## 테이블 구조

task 백엔드는 자체 마이그레이션을 실행해 메인 데이터베이스에 `sonamu_tasks` 스키마와 두 테이블을
만듭니다:

| 테이블                        | 내용                                                                                       |
| ----------------------------- | ------------------------------------------------------------------------------------------ |
| `sonamu_tasks.workflow_runs`  | 실행마다 한 행: `workflow_name`, `version`, `status`, `input`, `output`, `error`, `attempts`, 시각 |
| `sonamu_tasks.step_attempts`  | step 시도마다 한 행: `workflow_run_id`, `step_name`, `status`, `output`, `error`, 시각 |

## 모니터링

### 실행 중인 Workflow 확인

```typescript
// workflow_runs는 엔티티가 아닌 프레임워크 내부 테이블이므로 Knex를 직접 사용
import { BaseModel } from "sonamu";

const knex = BaseModel.getDB("r");
const runs = await knex
  .withSchema("sonamu_tasks")
  .table("workflow_runs")
  .where("status", "running")
  .select();
```

### 로그

```typescript
export const myWorkflow = workflow({ name: "my_workflow" }, async ({ logger, input }) => {
  logger.info("Workflow started", { input });
  logger.error("Error occurred", { error });
});
```
